# Learning Rules

How we get smarter without getting bloated.

## Two Layers of Memory

### 1. Playbook (`/_playbook/*.md`) — Reusable craft
- General patterns that apply across projects and clients
- Examples: bullet style, index formula, survey scale conventions
- **Save when**: a pattern has come up 2+ times or you explicitly say "save this"
- **Don't save**: one-off fixes, project-specific facts, client names

### 2. Project memory (auto memory) — Session-to-session context
- Your preferences, recurring corrections, project-specific conventions
- Examples: "always use fiscal year for this client," "prefers 3 bullets max per slide"
- **Save when**: you correct me or state a preference I should remember
- **Don't save**: task-specific details that won't recur

## What Triggers a Save
- You say "save this" or "remember this" → save immediately
- You correct the same thing twice → I propose saving the pattern
- A new reusable pattern emerges from a task → I propose (you approve before I write)
- I never save silently — you always see what's being proposed

## What Triggers a Prune
- Every ~10 sessions (or when you say "clean up playbook"): review each file
- **Drop**: entries that haven't been relevant in 5+ sessions
- **Merge**: entries that overlap or say the same thing differently
- **Sharpen**: replace vague rules with specific examples from our actual work
- Pruning is proposed, not automatic — I show you what I'd cut/merge, you approve

## Quality Over Quantity
- Each playbook file should stay under ~40 lines of content
- If a file is getting long, split by subtopic or prune the least-used entries
- Prefer concrete examples over abstract rules (show, don't tell)
- One strong example > three vague bullet points

## The Test for Any New Entry
Before saving, it must pass all three:
1. **Reusable?** Will this apply to future tasks, not just this one?
2. **Specific?** Is it concrete enough to change my output next time?
3. **Non-obvious?** Would I get it wrong without this note?

If no to any → don't save.
